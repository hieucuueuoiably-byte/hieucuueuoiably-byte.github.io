# 手机播放与比例优化（2026-10-02）

## 用户网络下的回归与恢复

用户反馈：页面能打开，旧版本可以开始播放但十几秒后卡顿；启用手机轻量视频及 DOM 原生渲染后，视频无法加载。此前本机线上播放至 30 秒的结果不能代表该用户网络。现已撤回自动切换 `/videos/mobile/` 和手机原生视频渲染，恢复 `work.video` 的原始地址、固定 `preload="metadata"` 和 WebGL 视频纹理显示；保留手机布局、较低画布分辨率和缓冲状态修复。轻量视频文件保留为未启用的候选资源。

下面轻量版本的数据是前一版实验记录，不代表当前启用策略。具体根因尚未在用户设备复现，恢复可播放仍需用户网络验证；原来的带宽卡顿也不能据此宣称已解决。

## 原因与现场证据

- 原视频共 18 条、141.76 MB。最大的横屏片为 29.81 MB，平均码率约 2.64 Mbps。
- 本机从线上 GitHub Pages 获取该视频的首个 1 MiB：HTTP 206，首字节 4.54 秒，总耗时 8.77 秒。这次链路的平均传输速度约 0.96 Mbps，低于原视频码率；这是一组现场采样，不代表所有用户的访问速度。
- 原控制器在 `readyState=2`（只有当前帧）时仍显示播放，导致缺少后续帧时无法正确提示缓冲。依据见 [MDN readyState](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/readyState)。
- 手机原来把每帧视频上传为 WebGL 纹理。此次移除手机端的该路径以减少额外绘制工作；尚未在实体手机测量 GPU 耗时。
- 390×844 屏幕原控制条高 110px，时间文字只有 8px；首页前景两个角色也有明显重叠。

## 当前行为

- 小屏、触摸设备、省流量模式或浏览器报告慢网络时，选择 `/videos/mobile/` 的轻量版本。选择在进入播放器时固定，旋转屏幕不会更换视频源。
- 新增 18 条 H.264/AAC 手机视频，竖屏 432×768、横屏 960×540，视频码率上限 600 kbps、音频 64 kbps。合计 53.20 MB，较原始视频减少 62.5%。视频时长与原始比例保持一致，`moov` 位于媒体数据之前，可先缓冲先播放。压缩参数和逐片指标见 [生成脚本](../scripts/prepare-mobile-videos.py) 与 [体积清单](mobile-video-manifest.json)。桌面原文件保留。
- 首次进入只请求元数据，点击播放后由浏览器继续加载。`preload` 是浏览器提示，实际下载量由浏览器决定，见 [MDN preload](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/preload)。
- 窄屏和短横屏使用 DOM 原生视频，保留纸张舞台与背景效果；显示真实缓冲状态，等待期间也可以暂停。
- 手机控制条分为两行，按钮保持 44px，时间文字 11px，390×844 时控制条高 98px。控制条跟随画面底部，横版视频在手机上也不会与底栏相隔过远。视频保留 9:16 / 16:9 比例，顶栏、画面和底栏留出间距，预留手机安全区域。
- 首页手机标题缩小，舞台收紧，章鱼与鸟缩小并分开摆放，脚下接触位置继续贴地。

## 验证

- `npm run verify:playback`：真实控制器事件监听的缺帧缓冲、恢复播放、暂停与解绑；旧代码在缓冲断言处失败，修复后通过。此检查已加入 GitHub Actions。
- `npm run build:pages`：TypeScript、生产构建与全部静态路由入口通过。
- ffprobe 与 MP4 结构检查：18 条手机视频编码、音频、比例、时长、码率与 faststart 全部通过。
- 浏览器生产预览：390×844、375×667、844×390、1280×720；播放时间前进、暂停、进度方向键、换片与原生视频显示已检查。

轻量版本降低了带宽需求和额外绘制工作。GitHub Pages 的访问延迟仍取决于用户网络；这里未做实体手机、蜂窝网络或 Safari 的持续性能测试。
